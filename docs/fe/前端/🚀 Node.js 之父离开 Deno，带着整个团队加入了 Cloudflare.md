# 🚀 Node.js 之父离开 Deno，带着整个团队加入了 Cloudflare

10 月 9 日，Ryan Dahl 在 Deno 官方博客发了一篇标题很短的公告，Deno 团队加入 Cloudflare。

这个名字你可能有点陌生。2009 年他写出了 Node.js，2018 年又亲手设计了它的继任者 Deno。

现在，他带着整个团队走了。👋

## 📰 一、先说这条消息本身

同一时间，Cloudflare 也发了一篇署名 Ryan Dahl 和 Kenton Varda 的文章。两边核心信息完全一致，主要有 4 条。

1️⃣ **Deno 整个团队加入 Cloudflare。** Ryan Dahl 和联合创始人 Bert Belder 会带头推进一个新项目。

2️⃣ **Deno 运行时还能用 1 年。** 官方继续提供月度发布，包含 bug 修复和安全补丁。1 年之后官方停止开发，代码保持开源。

3️⃣ **Deno Deploy 在 6 个月后关闭。** 付费客户会得到迁移到 Cloudflare Workers 的支持。

4️⃣ **JSR 包注册中心继续运营**，底层基础设施迁到 Cloudflare。

公告没有公布交易金额，双方用的词都是 "加入"。

## 🔍 二、Cloudflare 到底看上了什么

答案是一个叫 celld 的项目。🎯

Cloudflare 的开源运行时 workerd 一直在维护，它支持 Durable Objects，但只能跑单个实例。本地测试够用，跨机器扩展就撑不住了。

Deno 团队在 8 月发布了 celld。这个项目用 Rust 写成，外部依赖只有对象存储，能提供分布式计算、持久化状态和实时通信。⚙️

Cloudflare 的 Kenton Varda 说得很直白 😄，当 Deno 团队 8 月发布 celld 时，他们非常高兴。

接下来两边要把 celld 的代码和思路合并回 workerd。目标是让 Workers 编程模型既能跑在 Cloudflare 的网络上，也能跑在开发者自己的服务器上。

## 📜 三、Deno 这些年，留下了什么

回过头看，Deno 的履历相当漂亮。✨

- 🧩 **2009 年**，Dahl 在 JSConf EU 上发布 Node.js。这个让 JavaScript 走出浏览器的运行时，后来长成了前端和后端都无法绕开的基础设施。
- 💡 **2018 年**，他做了同一场演讲的续集，题目叫 "关于 Node 的 10 件让我后悔的事"。Deno 在这份反思里诞生。
- 🎉 **2020 年 5 月**，Deno 1.0 发布，第一天就拿到了大量关注。
- 🏢 **2021 年**，Deno 公司成立，Bert Belder 是联合创始人。
- 💰 **2022 年 6 月**，公司拿到 2100 万美元 A 轮融资，红杉资本领投，累计融资 2600 万美元。
- 🗄️ **2023 年**，Deno 推出 KV 存储，并开始认真兼容 npm 生态。
- 🚀 **2024 年 10 月**，Deno 2.0 发布，稳定性和生态兼容性都上了一个台阶。

## 🛠 四、Deno 的技术优点，值得记住

即便它即将停更，Deno 提出的很多设计已经影响了一整代工具链。

- 🔐 **默认安全。** 运行脚本时，你可以精确指定它能读哪些文件夹、能访问哪些网络地址。不加 `--allow` 参数，它什么也做不了。
- 📘 **TypeScript 是一等公民。** 不需要 tsconfig，不需要构建步骤，直接写 `.ts` 文件就能跑。
- 🌐 **拥抱 Web 标准。** fetch、WebSocket、Streams 这些 API 直接用，代码在浏览器和服务器之间搬来搬去，成本很低。
- 🧰 **自带完整工具链。** 格式化、lint、测试、打包、基准测试，一条命令全都有，不用再装一堆插件。
- 🧬 **去中心化的模块系统。** 通过 URL 直接引入依赖，配套的 JSR 注册中心也还在继续运营。

这些设计后来被 Node.js 和 Bun 大量借鉴。Dahl 自己最喜欢的权限模型，Node.js 在 2023 年也补上了。👍

## 🤔 五、他为什么选择离开

在 Hacker News 的评论区，Dahl 写了一段很坦率的解释。💬

他说这是共同决定，他本人也同意。他对 Deno 投入最多，也最希望它成功，但他不再认为这里是能做最重要工作的地方。

原话大意是，Deno 里有一些好想法，工程上也做得很好，但它最终没能解决足够大的问题。它被卷进了 Node 兼容性的引力井 🕳️，被迫表现得和 Node 一模一样。

在他看来，重写一个 Node 的收益，撑不起这份工作。边际的性能、体验和安全提升，都不足以成为理由。

他真正想做的是 celld 这样的新抽象。用他的话说，那是一套全新的服务器开发模型。🌱

## ✅ 六、如果你在用 Deno，现在该做什么

- ⏳ **Deno Deploy 用户。** 大约到 2027 年 4 月，服务就会关闭。有线上业务的团队，建议现在就排迁移计划。
- 🧭 **Deno CLI 用户。** 安全补丁预计在 2027 年 10 月停止。用 Deno 编译工具、跑脚本的团队，可以开始评估 Node.js、Bun 或 Workers 这几条路线。
- 📦 **JSR 上的包。** 短期安全，基础设施会迁移到 Cloudflare，暂时不用动。
- 👀 **最值得关注的问题。** 1 年之后，会不会有社区 fork 接手 Deno 运行时。代码是开源的，但维护一个 JavaScript 运行时需要全职工程师，而这些人刚刚集体去了 Cloudflare。

## 🌅 写在最后

17 年前，Dahl 用一个运行时改变了 JavaScript 的命运。8 年前，他用另一个运行时向自己开炮。💥

这一次，他放下自己亲手做的产品，去解决他觉得更重要的难题。

一个人愿意承认自己走到了该转身的地方，这件事本身就不容易。👏

至于 Deno 的故事会不会有人接着写下去，我们等 1 年后的答案。🕰️
